Window Functions
The Most Powerful Feature in Spark

rank, dense_rank, lag, lead, running totals — without losing a single row

// What Makes Window Functions Special

A window function computes an aggregate over a group of rows but — unlike groupBy — keeps every row in the output. Think of it as sliding a frame (window) over your data and computing something for each row within that frame. This is how you rank, calculate running totals, find previous/next row values, and much more.

// Core Window Functions
rank()

Rank within partition. Ties get the same rank, next rank skips (1,1,3).

dense_rank()

Like rank() but no gaps after ties (1,1,2). Preferred for leaderboards.

row_number()

Unique sequential number per row. No ties — breaks them arbitrarily.

lag(col, n)

Value from N rows BEFORE current row. Great for comparing to previous period.

lead(col, n)

Value from N rows AFTER current row. Useful for forecasting comparisons.

sum() / avg()

Running totals or rolling averages over the window frame.

first() / last()

First or last value within the window partition.

ntile(n)

Divides rows into N equal buckets. Perfect for percentile groupings.

// Window Functions in Action
day08_window_functions.py 
from pyspark.sql import SparkSession
from pyspark.sql import functions as F
from pyspark.sql.window import Window

spark = SparkSession.builder.appName("Day08").getOrCreate()

data = [
    ("Alice",   "Engineering", 95000.0),
    ("Bob",     "Marketing",   72000.0),
    ("Charlie", "Engineering", 88000.0),
    ("Diana",   "HR",          81000.0),
    ("Eve",     "Marketing",   67000.0),
    ("Frank",   "Engineering", 102000.0),
    ("Grace",   "Marketing",   72000.0),
]
df = spark.createDataFrame(data, ["name", "department", "salary"])

# ── Step 1: Define the Window ──────────────────────────
# partitionBy = group rows (like GROUP BY)
# orderBy     = sort rows within each partition
win_dept = Window.partitionBy("department").orderBy(F.col("salary").desc())

# ── Ranking functions ──────────────────────────────────
df = df.withColumn("rank",       F.rank().over(win_dept))
df = df.withColumn("dense_rank", F.dense_rank().over(win_dept))
df = df.withColumn("row_num",    F.row_number().over(win_dept))

# ── Running total within department ───────────────────
win_running = Window.partitionBy("department") \
    .orderBy("salary") \
    .rowsBetween(Window.unboundedPreceding, Window.currentRow)

df = df.withColumn("running_total", F.sum("salary").over(win_running))

# ── lag & lead: compare to previous/next row ──────────
win_lag = Window.partitionBy("department").orderBy("salary")
df = df.withColumn("prev_salary", F.lag("salary", 1).over(win_lag))
df = df.withColumn("next_salary", F.lead("salary", 1).over(win_lag))
df = df.withColumn("salary_diff",
    F.col("salary") - F.lag("salary", 1).over(win_lag)
)

# ── Salary vs dept average (no row collapse!) ─────────
win_avg = Window.partitionBy("department")
df = df.withColumn("dept_avg", F.avg("salary").over(win_avg))
df = df.withColumn("vs_avg",   F.col("salary") - F.col("dept_avg"))

# ── Top N per group (classic use case) ────────────────
top2_per_dept = df.filter(F.col("dense_rank") <= 2)
top2_per_dept.select("name", "department", "salary", "dense_rank").show()

spark.stop()

✦ The rowsBetween() Frame: Window.unboundedPreceding to Window.currentRow creates a cumulative (running) window. Use rangeBetween(-6, 0) for rolling windows like a 7-day moving average.
⚠️ Window functions trigger a shuffle when partitioning data. For very large datasets, ensure you're partitioning on a selective column to avoid all data landing in a single partition — which defeats the purpose of distributed computing.
// Key Takeaways
  • Window functions keep all rows — use them instead of groupBy whenever you need row-level output alongside group-level metrics.
  • Always define a Window spec first — partitionBy + orderBy — then apply functions with .over().
  • Use dense_rank() over rank() when gaps in ranking would confuse downstream consumers.
  • lag() and lead() are essential for time-series analysis and period-over-period comparisons.
  • The Top-N per group pattern (dense_rank <= N) is one of the most common interview and real-world patterns in data engineering.
