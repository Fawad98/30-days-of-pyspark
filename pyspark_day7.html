Handling Nulls in PySpark
Because Production Data Is Never Clean

isNull, fillna, dropna, coalesce — your null-busting toolkit

// Why Nulls Are Dangerous

Nulls in Spark behave like nulls in SQL — any arithmetic or comparison involving a null produces null. That means silent data loss. A filter like salary > 50000 will silently drop all rows where salary is null. Knowing how to detect, replace, and drop nulls is non-negotiable in production pipelines.

// The Null-Handling Toolkit
isNull() / isNotNull()

Check whether a column value is null or not. Use in filter conditions.

fillna() / fill()

Replace nulls with a default value. Accepts a dict to fill different columns differently.

dropna()

Drop rows that contain nulls. Control with how= and thresh= parameters.

F.coalesce()

Returns the first non-null value from a list of columns. SQL COALESCE equivalent.

F.when().otherwise()

Conditional null replacement — replace null with computed values, not just constants.

eqNullSafe() / <=>

Null-safe equality check. True when both sides are null. Regular == returns null.

// Handling Nulls in Practice
day07_nulls.py 
from pyspark.sql import SparkSession
from pyspark.sql import functions as F

spark = SparkSession.builder.appName("Day07").getOrCreate()

data = [
    (1, "Alice",   "Engineering", 95000.0),
    (2, "Bob",     None,          72000.0),
    (3, "Charlie", "Engineering", None),
    (4, None,     None,          None),
    (5, "Eve",     "Marketing",   67000.0),
]
df = spark.createDataFrame(
    data, ["id", "name", "department", "salary"]
)

# ── Detect nulls ───────────────────────────────────────
df.filter(F.col("salary").isNull()).show()
df.filter(F.col("name").isNotNull()).show()

# ── Count nulls per column ─────────────────────────────
df.select([
    F.sum(F.col(c).isNull().cast("int")).alias(c)
    for c in df.columns
]).show()

# ── dropna: remove rows with nulls ────────────────────
df.dropna().show()                        # drop if ANY null
df.dropna(how="all").show()               # drop only if ALL null
df.dropna(subset=["name", "salary"]).show() # drop if specific cols null
df.dropna(thresh=3).show()               # keep rows with 3+ non-null

# ── fillna: replace nulls with defaults ───────────────
df.fillna("Unknown").show()              # fill all string nulls
df.fillna(0.0, subset=["salary"]).show() # fill specific column
df.fillna({                               # fill each col differently
    "name":       "Unknown",
    "department": "Unassigned",
    "salary":     0.0
}).show()

# ── F.coalesce: first non-null from columns ───────────
df = df.withColumn(
    "dept_clean",
    F.coalesce(F.col("department"), F.lit("Unassigned"))
)

# ── Null-safe equals ───────────────────────────────────
# Regular ==  → null == null returns null (not True!)
# eqNullSafe  → null <=> null returns True
df.filter(F.col("department").eqNullSafe(None)).show()

# ── Replace null with computed value ──────────────────
avg_salary = df.agg(F.avg("salary")).collect()[0][0]
df = df.withColumn(
    "salary",
    F.when(F.col("salary").isNull(), avg_salary)
     .otherwise(F.col("salary"))
)

spark.stop()
// Null Count Per Column
+---+----+----------+------+ | id|name|department|salary| +---+----+----------+------+ | 0| 1| 2| 1| +---+----+----------+------+
✦ Best Practice: Always audit nulls at the start of your pipeline with the null count pattern above. Knowing exactly which columns have nulls — and how many — drives every downstream decision about dropping vs filling vs imputing.
⚠️ Never use == to compare with null. In Spark, F.col("dept") == None always returns null — not True or False. Always use .isNull() or .eqNullSafe() instead.
// Key Takeaways
  • Nulls propagate silently — always audit null counts before transforming data.
  • dropna(thresh=N) keeps rows with at least N non-null values — more flexible than how="any".
  • fillna({}) with a dict is the cleanest way to fill different columns with different defaults.
  • F.coalesce() is your go-to for fallback column logic — first non-null wins.
  • Replace nulls with computed values (mean, median) using F.when().otherwise() for smarter imputation.
