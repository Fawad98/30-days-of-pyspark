Joins in PySpark
Every Join Type + Broadcast Optimization

inner, left, semi, anti — and the trick that can 10x your join performance

// The 6 Join Types
inner

Only rows with matching keys in BOTH tables. Most common join.

left / left_outer

All rows from left + matched rows from right. Nulls where no match.

right / right_outer

All rows from right + matched rows from left. Rarely used — prefer left.

full / outer

All rows from both tables. Nulls wherever no match exists.

left_semi

Rows from left where a match exists in right. Like a filtered inner but returns only left columns.

left_anti

Rows from left where NO match exists in right. Perfect for finding orphaned records.

// All Join Types in Action
day06_joins.py 
from pyspark.sql import SparkSession
from pyspark.sql import functions as F

spark = SparkSession.builder.appName("Day06").getOrCreate()

# ── Two tables to join ─────────────────────────────────
employees = spark.createDataFrame([
    (1, "Alice",   101),
    (2, "Bob",     102),
    (3, "Charlie", 103),
    (4, "Diana",   None),  # no department
], ["emp_id", "name", "dept_id"])

departments = spark.createDataFrame([
    (101, "Engineering"),
    (102, "Marketing"),
    (104, "Finance"),    # no employees
], ["dept_id", "dept_name"])

# ── INNER: only matched rows ───────────────────────────
employees.join(departments, "dept_id", "inner").show()

# ── LEFT: all employees, nulls where no dept ──────────
employees.join(departments, "dept_id", "left").show()

# ── FULL OUTER: all rows from both tables ─────────────
employees.join(departments, "dept_id", "full").show()

# ── SEMI: employees that HAVE a department ────────────
employees.join(departments, "dept_id", "left_semi").show()

# ── ANTI: employees with NO department ────────────────
employees.join(departments, "dept_id", "left_anti").show()

# ── Joining on multiple keys ───────────────────────────
employees.join(
    departments,
    (employees["dept_id"] == departments["dept_id"]) &
    (employees["dept_id"].isNotNull()),
    "inner"
).drop(departments["dept_id"]).show()

# ── BROADCAST JOIN: the performance secret ────────────
# Use when one table is small (< 10MB). Sends it to all
# executors so no shuffle is needed = massive speedup.
employees.join(
    F.broadcast(departments),
    "dept_id",
    "inner"
).show()

spark.stop()
✦ Broadcast Join: Wrapping a small DataFrame with F.broadcast() tells Spark to send that entire table to every executor — eliminating the expensive shuffle step. Use it whenever one side of a join fits in memory (typically under 10MB). It's one of the highest-impact single-line optimizations in Spark.
⚠️ Duplicate column trap: When joining on columns with the same name, use the string shorthand join(df2, "dept_id") — Spark deduplicates automatically. If you use df1.dept_id == df2.dept_id, you get two dept_id columns and must drop one manually.
// Key Takeaways
  • left_semi and left_anti are underused gems — perfect for existence checks without column explosion.
  • Always prefer left over right — put your primary table on the left for readability.
  • Wrap small lookup tables with F.broadcast() — it eliminates shuffle and can dramatically speed up your job.
  • Use the string key shorthand to avoid duplicate columns after a join.
  • Joins trigger a shuffle by default — the most expensive operation in Spark. Minimize them where possible.
